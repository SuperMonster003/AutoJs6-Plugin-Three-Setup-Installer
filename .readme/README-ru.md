### Введение

******

3-Setup Installer устанавливает, обновляет, проверяет и удаляет приложения Android с собственного главного экрана, через AutoJs6 и скрипты, а также при открытии и передаче пакетов из других приложений. Поддерживаются подтверждение Android и привилегированные операции через Shizuku или Root.

AutoJs6 находит плагин через его Binder-сервис и передает файлы пакетов как файловые дескрипторы только для чтения; плагин разбирает пакет, выбирает способ авторизации, при необходимости показывает собственный диалог подтверждения и прогресса и сообщает этапы, прогресс и результат. Привилегированные операции выполняются в пользовательском сервисе Shizuku или root-сервисе libsu, который напрямую обращается к системному установщику пакетов.

Доступны подтверждение, прогресс, результаты и уведомления активной службы. После перезапуска процесса сохраняются записанные подтверждённые результаты, а незавершённые задачи помечаются отменёнными без автоматического возобновления или повтора. ### Возможности

******

Возможности этой предварительной версии:

- Форматы пакетов: `.apk`, `.apks`, `.xapk`, `.apkm`, `.apkz` и ZIP-архивы с APK внутри; split-пакеты подбираются под устройство; файлы `.aab` распознаются и описываются, но не устанавливаются.
- Способы авторизации: `none` использует подтверждение Android; `shizuku` и `root` дают привилегированные операции. По умолчанию `auto` выбирает доступные Shizuku, Root и системное подтверждение в таком порядке. В настройках можно менять порядок и включать способы; явно выбранный способ никогда не заменяется другим без уведомления.
- После успешной установки можно запросить попытку удаления источника. Понижение версии, тестовые пакеты, обход ограничения низкого targetSdk (Android 14+), указание установщика и другие пользователи требуют Shizuku или Root и по-прежнему подчиняются ограничениям Android.
- Установленные приложения можно искать по названию или имени пакета, сортировать по названию, времени установки или обновления и включать показ системных приложений. Можно открыть приложение или его системные сведения либо проверить и подтвердить удаление. Shizuku или Root затем удаляют без дополнительного системного запроса с возможностью сохранения данных; в остальных случаях используется подтверждение Android.
- Подтверждение показывает сведения о приложении, старую и новую версии, подписи и выбираемые компоненты APK. Операцию можно отменить; результат содержит действия после успеха или сведения об ошибке для копирования. В пакетной установке виден статус каждого элемента.
- Открывайте или передавайте один или несколько пакетов, включая файлы APKS из MT Manager. Несколько пакетов попадают в последовательную очередь. Неудачные внешние элементы можно повторить, пока доступны их URI и разрешение на чтение.
- Уведомления о ходе установки в службе переднего плана, отмене и результате. Отказ в разрешении на уведомления не препятствует установке.
- Настройки внешнего вида включают язык, ночной режим, цвет темы и значок лаунчера. Первые три по умолчанию следуют AutoJs6 и допускают локальные изменения; без хоста используются системные язык и режим и стандартный цвет. Значок имеет светлый, тёмный, автоматический и прозрачный режимы; автоматический следует системе с учётом кеша и масок лаунчера.
- Карточка на главном экране и настройки открывают одну страницу установщика по умолчанию. Она позволяет назначать и сбрасывать его с привилегиями или перейти к системным настройкам без них. Политики OEM могут блокировать изменение или требовать сброса предыдущего обработчика. Скрипты сохраняют `installer.isDefault`, `installer.setDefault` и `setDefaultAsync`; результаты отражают ответ устройства.
- API скриптов `installer` (псевдоним `$installer`) предлагает синхронную форму, `...Async` и сеансы для одиночной, пакетной и split-установки, удаления, проверки, запросов способов авторизации и пользователей, а также настройки установщика по умолчанию. Ошибки представлены `InstallerError` со стабильным `code` (требуется AutoJs6 >= 6.8.0 (5300)).
- Главный экран показывает доступность и авторизацию Shizuku/Root, текущий установщик по умолчанию, активные задачи и последние установки. Выберите несколько пакетов через системный выбор файлов для последовательной установки, продолжения после отдельных ошибок или отмены оставшихся элементов.
- Локальная закрытая история хранит до 200 элементов: пакет, название, старую/новую версии, результат, время, источник (хост/скрипт/внешний/главная), способ авторизации и сведения об ошибке. Можно удалить запись или очистить историю без удаления приложений и исходных файлов. После завершения процесса незавершённые элементы становятся отменёнными и не возобновляются автоматически.
- Настройки сохраняют порядок и включённые способы авторизации, параметры установки и уведомления о прогрессе. Установка с главного экрана и из внешних приложений по умолчанию использует `dialog`; явно сохранённые `auto` или `silent` применяются. Запросы хоста/скриптов сохраняют явные параметры, а API скриптов по-прежнему использует `auto` по умолчанию. Выбор сохраняется только после подтверждения.
- В настройках доступны сведения о приложении и встроенная история версий на десяти языках. Ручная проверка обновлений использует GitHub Releases API плагина с интервалом 12 часов, кешированием результатов и управлением игнорируемыми версиями. Страницы выпусков открываются в браузере; обновления не скачиваются и не устанавливаются автоматически.

### Использование

******

1. Установите APK плагина с официальной страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/releases) на Android 7.0 или новее. Собственный значок лаунчера открывает главный экран.
2. На главном экране проверьте авторизацию и установщик по умолчанию, затем кнопкой добавления выберите один или несколько пакетов. Проверьте диалог установки перед подтверждением; прогресс и последние записи видны на главном экране.
3. Для интеграции с AutoJs6 используйте сборку 5299 (6.8.0) или новее и включите `3-Setup Installer` в центре плагинов. API скриптов требует сборку 5300 или новее.
4. Используйте действие установки в AutoJs6 или выберите 3-Setup Installer при открытии или передаче файлов пакетов. Если появился диалог подтверждения, проверьте приложение и параметры перед установкой. Для привилегированного способа заранее подготовьте авторизацию Shizuku или Root.
5. Меню главного экрана открывает установленные приложения и настройки. Проверьте локальные параметры установки, внешний вид, значок и уведомления; сведения о приложении, история версий и ручная проверка обновлений находятся в настройках.

### Способы авторизации

******

Что умеет каждый способ и что ему нужно:

- `none`: стандартная сессия PackageInstaller; Android запрашивает у пользователя подтверждение каждой установки, split-пакеты поддерживаются, привилегированные параметры недоступны.
- `shizuku`: требуется работающий Shizuku (запущенный через беспроводную отладку, ADB или Root) и разрешение для плагина. Права shell позволяют выполнять тихую установку и удаление, а также операции для других пользователей.
- `root`: требует root-менеджера, выдавшего плагину `su`; предоставляет те же операции, что и Shizuku, через root-сервис libsu. Понижение версии на обычной (user) прошивке по-прежнему удается только для debuggable-приложений: это правило фреймворка, а не ограничение плагина.
- **Примечание:** При доступных привилегиях запросы хоста с `interaction: 'auto'` выполняют тихую установку без предварительного открытия подтверждения. Если Android требует подтверждение, `auto` разрешает его и добавляет запись в `notes`. Используйте `interaction: 'dialog'` для подтверждения перед установкой или `interaction: 'silent'` для отказа при необходимости системного подтверждения. API скриптов использует это же поведение по умолчанию.
- Настройки сохраняют порядок и включённые способы авторизации, параметры установки и уведомления о прогрессе. Установка с главного экрана и из внешних приложений по умолчанию использует `dialog`; явно сохранённые `auto` или `silent` применяются. Запросы хоста/скриптов сохраняют явные параметры, а API скриптов по-прежнему использует `auto` по умолчанию. Выбор сохраняется только после подтверждения.

### Быстрый старт

******

Шаблонные функции для установки, пакетов и сеансов (требуется AutoJs6 >= 6.8.0 (5300)). Выберите и проверьте источники перед вызовом функции. Пример не запускает установку, удаление или смену установщика по умолчанию автоматически.:

```js
// Read-only probe. The functions below run only when explicitly called with chosen sources.
console.log(installer.status);

// An already authorized Shizuku service is required; silent never falls back to a dialog.
let installChosen = source => installer.install(source, {
    authorizer: 'shizuku', interaction: 'silent', deleteSource: false,
});

// An array means independent applications, including an array containing one source.
let installBatchChosen = sources => installer.installAsync(sources, {
    interaction: 'dialog', continueOnError: true, deleteSource: false,
}).then(results => results.forEach(result => console.log(result.ok, result.packageName, result.error)))
    .catch(error => console.error(error.code, error.systemMessage));

// A source may also be { splits: [...] } for one application's split files.
let watchChosen = source => {
    let session = installer.session(source, { interaction: 'dialog', deleteSource: false });
    session.on('progress', progress => console.log(Math.round(progress * 100) + '%'))
        .on('complete', result => console.log(result))
        .on('error', error => console.error(error.code, error.systemMessage));
    return session;
};
```

### Частые вопросы

******

- **Почему установка все еще требует подтверждения?** `none` всегда использует системное подтверждение. Подготовьте авторизацию и выберите Shizuku или Root в диалоге установки. Android или политика устройства все равно могут потребовать подтверждение.
- **Можно ли установить `.aab`?** Нет. Android App Bundle является форматом публикации; сначала преобразуйте его с помощью bundletool в набор `.apks`. Плагин распознает файлы `.aab` и показывает сведения о пакете и модулях.
- **Какое имя пакета установщика использовать в HyperOS?** Если Shizuku запущен через ADB или беспроводную отладку, без указанного имени используется `com.android.shell`. На проверенном Xiaomi 23046RP50C / HyperOS / API 35 новые установки и обновления без диалога записали это значение. Явно указанные `com.android.shell` и имя пакета самого плагина также были приняты и записаны как запрошено. Другие имена или версии ROM зависят от ответа системы.
- **ColorOS или другая ROM требует активировать плагин. Что делать?** После установки или принудительной остановки Android может сохранять приложение остановленным до действия пользователя. Используйте действие активации в центре плагинов AutoJs6, если оно предложено, либо откройте 3-Setup Installer через его значок и повторите попытку. Это соответствует [правилам остановленного состояния Android](https://developer.android.com/reference/android/content/pm/ApplicationInfo#FLAG_STOPPED). Поведение именно ColorOS на устройстве пока не проверено.
- **Почему не удается назначить установщик по умолчанию?** ROM может отклонить изменение. В старых версиях Android существующий обработчик APK может требовать сначала сбросить его настройки по умолчанию в системных настройках; следуйте указаниям страницы. Если система не предоставляет такого действия, замена не гарантируется. Версия 1.0.0 не гарантирует постоянное закрепление даже с Shizuku или Root.
- **Почему источник не удален?** Удаление выполняется только после успешной установки. При ошибке, отмене или истечении времени установки источник всегда сохраняется. Ошибка удаления не меняет успешный результат установки, а внешний поставщик может отказать в удалении. Для скриптов хост применяет `deleteSource` к путям и источникам `file://`, сохраняя источники `content://`. Проверьте `sourceDeleted` и `notes`.
- **Можно повторить или возобновить установку?** Повторная попытка для внешнего URI возможна, пока доступны источник и доступ к нему. После освобождения источника или разрешения откройте пакет заново. После перезапуска процесса восстановленный экран показывает сохраненные подтвержденные результаты и отмечает незавершенные элементы как прерванные. Экран доступен только для чтения и не запускает установку или повторную попытку автоматически. Перед новой попыткой проверьте фактическое состояние приложения.

### Разрешения и безопасность

******

Плагин соблюдает явные границы:

- Точки входа Binder защищены сигнатурным разрешением `org.autojs.permission.PLUGIN`, поэтому доступ к ним есть только у AutoJs6; внешний пункт "Открыть с помощью" принимает только файлы пакетов и никогда не запускает скрипты.
- REQUEST_INSTALL_PACKAGES и REQUEST_DELETE_PACKAGES обеспечивают подтверждение Android. QUERY_ALL_PACKAGES используется для управления установленными приложениями, сравнения версий и подписей и определения установщика по умолчанию.
- FOREGROUND_SERVICE и FOREGROUND_SERVICE_DATA_SYNC обеспечивают фоновую работу установки; POST_NOTIFICATIONS разрешает уведомления о ходе и результате. Отсутствие разрешения на уведомления не блокирует установку.
- Shizuku и Root используются только для запущенной вами операции; привилегированный сервис не хранит состояние, не держит открытый shell между операциями и недоступен извне плагина.
- Установка, проверка, история и управление приложениями работают офлайн. INTERNET используется только при ручной проверке версий через фиксированный GitHub Releases API плагина с интервалом 12 часов. Фоновые проверки обновлений и отправка пакетов не выполняются.
- Исходные пакеты открываются только для чтения. История сохраняет ограниченные метаданные и результаты без содержимого пакетов и URI источников; пути в ошибках скрываются. Закрытое хранилище исключено из резервных копий. Удаление записи не удаляет приложение или его исходный файл.

Получайте плагин только со страницы официальных [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/releases) или из центра плагинов AutoJs6. Пакеты из неизвестных источников могут не пройти проверку хоста или нести риски, даже если номер версии выглядит одинаково.

### Интерфейс плагина

******

Следующая информация предназначена разработчикам хоста AutoJs6 и плагинов; хост использует эти идентификаторы для обнаружения плагина и согласования совместимости:

```text
application id: io.github.supermonster003.autojs6.plugin.three.setup.installer
plugin id: three-setup-installer
engine: installer
variant: default
service action: org.autojs.plugin.INSTALLER
service category: installer
info action: org.autojs.plugin.INFO
aidl interface: org.autojs.plugin.installer.api.IInstallerPlugin
minimum host build: 5299 (6.8.0)
```

`ThreeSetupInstallerPluginService` отвечает на `org.autojs.plugin.INSTALLER` (category `installer`) и начиная с этапа P1 реализует контракт хоста installer-api `org.autojs.plugin.installer.api.IInstallerPlugin`. `ThreeSetupInstallerPluginInfoService` отвечает на `org.autojs.plugin.INFO` объектом PluginInfo. `WakeActivity` позволяет хосту активировать плагин.

### Сборка и проверка

******

Этот раздел предназначен разработчикам, желающим собрать плагин из исходного кода; обычные пользователи могут просто установить готовый APK со страницы Releases.

Собрать отладочный APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Запустить модульные тесты JVM и собрать APK инструментальных тестов:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

Собрать выпускной APK:

```powershell
.\gradlew.bat :app:assembleRelease
```

Собрать выпускной артефакт и добавить версию и контрольную сумму CRC32 к имени файла:

```powershell
.\gradlew.bat :app:appendDigestToReleasedFiles
```

Проверить, что источники многоязычной документации и сгенерированные артефакты синхронизированы (также проверяется в CI):

```powershell
py .python\generate_markdown.py --check
```

Для сборки требуются JDK 21 или новее и Android SDK 37; версии Gradle и плагинов централизованно управляются через `version.properties` и `io.github.supermonster003.autojs6-platform-versions`.
