# v1.1.0

###### 2026/10/02

* `Функция` `dhizuku`: требуются Android 8.0 (API 26)+, активный владелец устройства/профиля Dhizuku и разрешение для этого плагина. Операции выполняются только в текущем пользователе владельца, а установщиком указывается реальный пакет владельца. Недоступны возможности shell/root: понижение версии, тестовые пакеты, обход ограничения низкого targetSdk, другие пользователи, произвольный установщик и удаление с сохранением данных. Плагин не назначает владельца.
* `Функция` Страница установщика по умолчанию различает обычные предпочтения и постоянную политику. Обычные предпочтения используют Shizuku или Root и зависят от ограничений прошивки. Постоянная политика через Dhizuku доступна на API 26-33; на API 34+ запрос отклоняется до изменений, поскольку нельзя проверить обратный вызов владельца. Root использует помощник с системным UID только в пользователе 0 на поддерживаемых устройствах. Конкурирующие постоянные политики не перезаписываются. `persistentConfigured` - запись о ранее успешной настройке, а не доказательство текущей политики; пассивная проверка сообщает только `preferred` или `none`.
* `Функция` `interaction: 'notification'` - режим установки: подтверждение, отмена, ход операции и результат показаны в уведомлениях, без диалогов установки плагина. Для системного подтверждения Android нужно нажать уведомление. Разрешение на уведомления, уведомления приложения и его канал установки должны быть включены; иначе запрос завершается с `NOTIFICATION_UNAVAILABLE`. Запрет уведомлений не блокирует другие режимы. Удаление не поддерживает `notification`.
* `Улучшение` `none` использует подтверждение Android. В новых настройках `auto` проверяет доступные методы в порядке `shizuku -> root -> dhizuku -> none`; каждый метод можно переместить или отключить. Сохраненные настройки трех методов сохраняют относительный порядок и включенное состояние; Dhizuku добавляется перед `none`, но остается отключенным. Явно выбранный метод не заменяется другим.
* `Улучшение` Настройки сохраняют порядок и включенное состояние методов авторизации, параметры установки и уведомлений. Установка с главного экрана или из внешнего источника по умолчанию использует `dialog`; можно явно выбрать `auto`, `silent` или `notification`. Кнопки установки в интерфейсе хоста используют `dialog`, скрипты сохраняют явные параметры и по умолчанию используют `auto`. Изменения сохраняются после подтверждения.
* `Зависимость` Добавлен Dhizuku API 2.6.0 (MIT) для авторизации через владельца устройства/профиля
* `Зависимость` `installer-api.aar` обновлен до контракта V2 (MPL 2.0), с сохранением согласования V1 и добавлением метода постоянного установщика в конец интерфейса; происхождение и SHA-256 указаны в Third-Party Notices; AutoJs6 >= 6.8.0 (5307).

# v1.0.0

###### 2026/10/02

* `Подсказка` 1.0.0 описывает реализованные ниже функции установки, управления приложениями и скриптов. Официальная публикация в GitHub Releases и включение в центр плагинов ещё не выполнены. Интеграция требует AutoJs6 >= 6.8.0 (5299), а API скриптов `installer` требует сборку 5300 или новее. Проверенные устройства и оставшиеся проверки указаны в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md).
* `Функция` 3-Setup Installer устанавливает, обновляет, проверяет и удаляет приложения Android с собственного главного экрана, через AutoJs6 и скрипты, а также при открытии и передаче пакетов из других приложений. Поддерживаются подтверждение Android и привилегированные операции через Shizuku или Root
* `Функция` Форматы пакетов: `.apk`, `.apks`, `.xapk`, `.apkm`, `.apkz` и ZIP-архивы с APK внутри; split-пакеты подбираются под устройство; файлы `.aab` распознаются и описываются, но не устанавливаются
* `Функция` После успешной установки можно запросить попытку удаления источника. Понижение версии, тестовые пакеты, обход ограничения низкого targetSdk (Android 14+), указание установщика и другие пользователи требуют Shizuku или Root и по-прежнему подчиняются ограничениям Android
* `Функция` API скриптов `installer` (псевдоним `$installer`) предлагает синхронную форму, `...Async` и сеансы для одиночной, пакетной и split-установки, удаления, проверки, запросов способов авторизации и пользователей, а также настройки установщика по умолчанию. Ошибки представлены `InstallerError` со стабильным `code` (требуется AutoJs6 >= 6.8.0 (5300)). Скрипты по умолчанию используют `interaction: 'auto'` и при наличии привилегий устанавливают без диалога. Действия установки в интерфейсе хоста используют `dialog`. Если Android требует подтверждение, `auto` разрешает его и отмечает это в `notes`. Для подтверждения перед установкой явно укажите `interaction: 'dialog'`. Явный `silent` завершается с `AUTHORIZER_REQUIRED`, если привилегий нет или нужно системное подтверждение
* `Функция` Главный экран показывает доступность и авторизацию Shizuku/Root, текущий установщик по умолчанию, активные задачи и последние установки. Выберите несколько пакетов через системный выбор файлов для последовательной установки, продолжения после отдельных ошибок или отмены оставшихся элементов
* `Функция` Подтверждение показывает сведения о приложении, старую и новую версии, подписи и выбираемые компоненты APK. Операцию можно отменить; результат содержит действия после успеха или сведения об ошибке для копирования. В пакетной установке виден статус каждого элемента
* `Функция` Уведомления о ходе установки в службе переднего плана, отмене и результате. Отказ в разрешении на уведомления не препятствует установке
* `Функция` Открывайте или передавайте один или несколько пакетов, включая файлы APKS из MT Manager. Несколько пакетов попадают в последовательную очередь. Неудачные внешние элементы можно повторить, пока доступны их URI и разрешение на чтение
* `Функция` Установленные приложения можно искать по названию или имени пакета, сортировать по названию, времени установки или обновления и включать показ системных приложений. Можно открыть приложение или его системные сведения либо проверить и подтвердить удаление. Shizuku или Root затем удаляют без дополнительного системного запроса с возможностью сохранения данных; в остальных случаях используется подтверждение Android
* `Функция` Карточка на главном экране и настройки открывают одну страницу установщика по умолчанию. Она позволяет назначать и сбрасывать его с привилегиями или перейти к системным настройкам без них. Политики OEM могут блокировать изменение или требовать сброса предыдущего обработчика. Скрипты сохраняют `installer.isDefault`, `installer.setDefault` и `setDefaultAsync`; результаты отражают ответ устройства
* `Функция` Настройки сохраняют порядок и включённые способы авторизации, параметры установки и уведомления о прогрессе. Установка с главного экрана и из внешних приложений по умолчанию использует `dialog`; явно сохранённые `auto` или `silent` применяются. Запросы хоста/скриптов сохраняют явные параметры, а API скриптов по-прежнему использует `auto` по умолчанию. Выбор сохраняется только после подтверждения
* `Функция` Настройки внешнего вида включают язык, ночной режим, цвет темы и значок лаунчера. Первые три по умолчанию следуют AutoJs6 и допускают локальные изменения; без хоста используются системные язык и режим и стандартный цвет. Значок имеет светлый, тёмный, автоматический и прозрачный режимы; автоматический следует системе с учётом кеша и масок лаунчера
* `Функция` Локальная закрытая история хранит до 200 элементов: пакет, название, старую/новую версии, результат, время, источник (хост/скрипт/внешний/главная), способ авторизации и сведения об ошибке. Можно удалить запись или очистить историю без удаления приложений и исходных файлов. После завершения процесса незавершённые элементы становятся отменёнными и не возобновляются автоматически
* `Функция` В настройках доступны сведения о приложении и встроенная история версий на десяти языках. Ручная проверка обновлений использует GitHub Releases API плагина с интервалом 12 часов, кешированием результатов и управлением игнорируемыми версиями. Страницы выпусков открываются в браузере; обновления не скачиваются и не устанавливаются автоматически
* `Функция` README, описание для центра плагинов и журнал изменений на 10 языках
* `Улучшение` Источники с произвольным доступом не требуют полной копии в кэше, а потоки временно сохраняются по необходимости. Поддерживаются разделенные пакеты в ZIP, AAB доступен только для проверки, измененные источники отклоняются
* `Улучшение` Удаление выполняется только после успешной установки. При ошибке, отмене или истечении времени установки источник всегда сохраняется. Ошибка удаления не меняет успешный результат установки, а внешний поставщик может отказать в удалении. Для скриптов хост применяет `deleteSource` к путям и источникам `file://`, сохраняя источники `content://`. Проверьте `sourceDeleted` и `notes`. В пакетной установке для подтверждённо успешных элементов применяется `deleteSource`, даже если другой элемент завершился ошибкой или оставшаяся очередь отменена
* `Улучшение` Установки одного пакета выполняются последовательно для всех пользователей и способов авторизации, с отменой и тайм-аутом ожидания; неактивные временные каталоги старше 24 часов безопасно очищаются при автономном запуске
* `Улучшение` При разрыве привилегированного соединения во время его установления допускается одна автоматическая повторная попытка; уже начатые установка и удаление автоматически не повторяются
