3-Setup Installer は Android アプリのインストール, 更新, 検査, アンインストールを行います. ホーム画面, AutoJs6 のインストール操作とスクリプト, 他のアプリが開いたり共有したりしたパッケージからインストールを始められます. 既定では Android が確認し, Shizuku, Root または Dhizuku を許可するとサイレントインストールもできます. AutoJs6 に接続しなくても単独で使えます.

### はじめに

1. ランチャーから 3-Setup Installer を開きます. サイレントインストールを使うときは, ホーム画面の "権限" で Shizuku, Root または Dhizuku の "権限を付与" をタップします.
2. "インストールパッケージを選択" をタップし, APK, APKS, XAPK などのパッケージを 1 つ以上選びます.
3. インストールダイアログでバージョン, 署名, 権限を確認し, "インストール" をタップします.
4. AutoJs6 の "プラグインセンター" で本プラグインを有効にすると, AutoJs6 のインストール操作でも同じダイアログが表示されます. 他のアプリでパッケージを開くときや共有するときにも 3-Setup Installer を選べます.

### 主な機能

- **インストールダイアログ**: バージョンの変化, サイズ, SDK と署名の比較を表示し, 新規インストール, 更新, 再インストール, ダウングレードを区別します. APK コンポーネント, 権限, "その他のオプション" を展開して調整できます.
- **認証方法**: 許可がないときは Android がその都度確認します. Shizuku, Root または Dhizuku を許可すると, サイレントインストール, ダウングレードの許可, 権限の付与などができます. 設定の "認証方法の順序と有効化" で自動選択の順序を決めます.
- **一括インストールと記録**: 複数のアプリを一度にインストールでき, ホーム画面に実行中のタスクと "最近のインストール" を表示します. 記録にはアプリ情報と結果だけを保存し, パッケージは保存しません.
- **インストール済みアプリ**: ホーム画面の "その他" メニューから開き, アプリの検索, 並べ替え, アプリ情報の表示, アンインストールができます.
- **既定のインストーラー**: APK ファイルを開く既定のアプリに本プラグインを設定します. 設定できるかどうかは認証方法とシステムの制限によります.
- **インストールプロファイルと拒否リスト**: 設定でインストール元とパッケージ名の接頭辞ごとにインストールオプションを指定したり, "パッケージ拒否リスト" と "共有 UID 拒否リスト" で特定のアプリのインストールを阻止したりできます.
- **署名の確認**: 新しいパッケージの署名がインストール済みアプリと一致しない場合は既定で阻止し, インストールダイアログでその項目に限り 1 回だけ許可できます.
- **設定**: "既定の操作方法", 外観, ランチャーアイコン, 通知を調整できます. "リリース履歴" の表示や手動の "更新を確認" もここから行えます.

### スクリプトでの使い方

AutoJs6 のスクリプトは `installer` モジュールでアプリをインストール, 検査, アンインストールします. 次の例はインストールダイアログを表示し, ユーザーが確認してからインストールします. 同期メソッドは UI スレッドではなくスクリプトスレッドで呼び出してください:

```js
console.log(installer.status);
try {
    let result = installer.install('./app.apk', { interaction: 'dialog' });
    console.log(result.packageName, result.versionName);
} catch (e) {
    console.error(e.code, e.message);
}
```

- `interaction` を省略すると `auto` になり, 特権の認証方法が許可されていればサイレントでインストールし, そうでなければ Android が確認を求めます.
- 配列を渡すと一括インストールになり, ソースの順に結果を返します. 各項目の `ok` と `error` を確認してください. `installAsync` は Promise を返し, UI スレッドでも使えます.
- `installer.inspect(source)` はパッケージ名やバージョンなどの情報を読み取るだけで, インストールはしません.
- すべてのオプションとイベントは [AutoJs6 ドキュメント > installer](https://docs.autojs6.com/#/installer) を参照してください.

### 動作要件

- Android 7.0 以降. AutoJs6 と組み合わせて使うには AutoJs6 6.8.0 以降が必要です. 単独で使う場合は AutoJs6 は不要です.
- Shizuku, Root, Dhizuku はいずれも任意で, サイレントインストールや特権オプションを使うときだけ必要です. Dhizuku には Android 8.0 以降が必要です.
- インストールとアンインストールの権限は Android の確認を求めるために, アプリ一覧の権限はインストール済みアプリ, バージョン, 署名の比較に, 通知の権限は通知からのインストールと進行状況の通知に使います.
- ネットワークはプラグインの更新を手動で確認するときだけ使い, パッケージをアップロードすることはありません.

### よくある質問

**許可済みでもインストールの確認が必要になる理由**

Android やメーカーのシステムのポリシーにより, ユーザーの確認が求められることがあります. このとき "自動" では Android の確認に切り替わり, サイレントの方式では理由を示して失敗します.

**インストール後にユーザー補助サービスをオンにできない理由**

Android 13 以降, ローカルファイルとしてインストールされたアプリはユーザー補助などの制限付き設定を使えません. Shizuku または Root でインストールした場合は, 既定でローカルファイルとして扱われません. 信頼できるアプリなら, システム設定のアプリ情報ページの右上のメニューで制限付き設定を許可してから, ユーザー補助サービスをオンにしてください. 項目の場所はシステムによって異なります.

**.aab ファイルをインストールできない理由**

Android App Bundle は配布用の形式で, 直接インストールできません. 先に bundletool で .apks パッケージに変換してください. プラグインでは .aab ファイルのパッケージ名とモジュールの情報を表示できます.

**ダウングレードを許可しても失敗する理由**

"ダウングレードを許可" はシステムへの要求にすぎず, 受け入れられるかどうかはシステムのバージョン, 認証方法, アプリがデバッグ可能かどうかで決まります. 失敗した場合は, システムが返したメッセージが結果に含まれます.

認証方法, インストールオプション, 権限の詳しい説明は [プロジェクトのホームページ](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer) を参照してください.
