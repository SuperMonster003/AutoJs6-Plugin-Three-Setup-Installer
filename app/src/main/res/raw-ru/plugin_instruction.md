3-Setup Installer устанавливает, обновляет, проверяет и удаляет приложения Android. Установку можно начать с его главного экрана, из действий установки и скриптов AutoJs6 или с пакетов, которые открывают или передают другие приложения; по умолчанию каждую установку подтверждает Android, а после авторизации Shizuku, Root или Dhizuku возможна и тихая установка. Плагин работает и самостоятельно, без AutoJs6.

### Начало работы

1. Откройте 3-Setup Installer из лаунчера. Для тихой установки нажмите "Авторизовать" у Shizuku, Root или Dhizuku в разделе "Авторизация" на главном экране.
2. Нажмите "Выбрать пакеты для установки" и выберите один или несколько пакетов APK, APKS, XAPK и подобных.
3. Проверьте версию, подпись и разрешения в диалоге установки, затем нажмите "Установить".
4. После включения плагина в разделе "Центр плагинов" AutoJs6 действия установки в AutoJs6 показывают тот же диалог; 3-Setup Installer также можно выбрать, когда другое приложение открывает или передаёт пакет.

### Основные возможности

- **Диалог установки**: показывает изменение версии, размер, сравнение SDK и подписи и отмечает новую установку, обновление, переустановку или понижение версии; компоненты APK, разрешения и "Дополнительные параметры" можно развернуть и настроить.
- **Авторизация**: без авторизации Android подтверждает каждую установку; с Shizuku, Root или Dhizuku возможны тихая установка, понижение версии, выдача разрешений и другое. Параметр "Порядок и включение способов авторизации" в настройках задаёт порядок автоматического выбора.
- **Пакетная установка и журнал**: можно установить несколько приложений сразу, а на главном экране видны текущие задачи и "Последние установки"; журнал хранит только сведения о приложениях и результаты, но не сами пакеты.
- **Установленные приложения**: открываются из меню "Ещё" на главном экране; здесь можно искать, сортировать, смотреть сведения о приложении или удалять его.
- **Установщик по умолчанию**: назначает плагин приложением по умолчанию для открытия файлов APK; возможность зависит от авторизации и ограничений системы.
- **Профили установки и списки блокировки**: в настройках можно заранее задать параметры установки по источнику и префиксу имени пакета или запретить установку отдельных приложений через "Список блокировки пакетов" и "Список блокировки общих UID".
- **Проверка подписи**: пакет, подпись которого отличается от подписи установленного приложения, по умолчанию блокируется; разрешить его можно только один раз для этого элемента в диалоге установки.
- **Настройки**: здесь задаются "Взаимодействие по умолчанию", оформление, значок в лаунчере и уведомления, открывается "История выпусков", а кнопка "Проверить обновления" запускает проверку вручную.

### Использование в скриптах

Скрипты AutoJs6 устанавливают, проверяют и удаляют приложения через модуль `installer`. Пример ниже показывает диалог установки и устанавливает пакет после подтверждения пользователем; синхронные методы нужно вызывать в потоке скрипта, а не в потоке UI:

```js
console.log(installer.status);
try {
    let result = installer.install('./app.apk', { interaction: 'dialog' });
    console.log(result.packageName, result.versionName);
} catch (e) {
    console.error(e.code, e.message);
}
```

- Без `interaction` используется режим `auto`: при доступной привилегированной авторизации установка тихая, иначе Android запрашивает подтверждение.
- Массив запускает пакетную установку и возвращает результаты в порядке источников; проверяйте `ok` и `error` у каждого элемента. `installAsync` возвращает Promise и подходит для потока UI.
- `installer.inspect(source)` только читает имя пакета, версию и другие сведения, не устанавливая его.
- Все параметры и события описаны в [Документация AutoJs6 > installer](https://docs.autojs6.com/#/installer).

### Требования

- Android 7.0 или новее. Для работы с AutoJs6 нужен AutoJs6 6.8.0 или новее; для самостоятельного использования AutoJs6 не нужен.
- Shizuku, Root и Dhizuku необязательны и нужны только для тихой установки или привилегированных параметров; Dhizuku требует Android 8.0 или новее.
- Разрешения на установку и удаление нужны для запроса подтверждения Android, разрешение на список приложений - для установленных приложений, версий и сравнения подписей, разрешение на уведомления - для установки через уведомления и уведомлений о ходе.
- Сеть используется только при ручной проверке обновлений плагина; пакеты никуда не отправляются.

### Частые вопросы

**Почему после авторизации всё ещё нужно подтверждение**

Политика Android или производителя может по-прежнему требовать подтверждения. Тогда режим "Автоматически" переходит к подтверждению Android, а тихий режим завершается ошибкой с указанием причины.

**Почему после установки не удаётся включить службу специальных возможностей**

Начиная с Android 13 приложения, установленные из локального файла, не могут использовать специальные возможности и другие ограниченные настройки; установки через Shizuku или Root по умолчанию не помечаются как локальный файл. Для доверенного приложения разрешите ограниченные настройки в меню в правом верхнем углу его страницы сведений в системных настройках, затем включите службу; расположение пункта зависит от системы.

**Почему нельзя установить файлы .aab**

Android App Bundle - формат публикации, его нельзя установить напрямую. Сначала преобразуйте его в пакет .apks с помощью bundletool; плагин может показать имя пакета и модули файла .aab.

**Почему понижение версии не удаётся даже при разрешении**

"Разрешить понижение версии" лишь передаёт запрос системе; примет ли она его, зависит от версии системы, способа авторизации и того, допускает ли приложение отладку. При неудаче результат содержит сообщение, возвращённое системой.
