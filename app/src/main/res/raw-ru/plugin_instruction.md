3-Setup Installer устанавливает, обновляет, проверяет и удаляет приложения Android с собственного главного экрана, через AutoJs6 и скрипты, а также при открытии и передаче пакетов из других приложений. Поддерживаются подтверждение Android и привилегированные операции через Shizuku, Root или Dhizuku.

1.2.0 описывает реализованные ниже функции установки, управления приложениями и скриптов. Официальная публикация в GitHub Releases и включение в центр плагинов ещё не выполнены. Интеграция требует AutoJs6 >= 6.8.0 (5299), а API скриптов `installer` требует сборку 5300 или новее. Проверенные устройства и оставшиеся проверки указаны в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md). Dhizuku, установка через уведомления и параметры постоянного установщика в скриптах требуют AutoJs6 6.8.0, сборка 5307 или новее, с контрактом установщика V2. Базовая интеграция с хостом доступна со сборки 5299, методы скриптов V1 - со сборки 5300.

Расширенные параметры требуют AutoJs6 5308+ и V3 с `advanced-install-options`. Без переопределения профилем пропуск сохраняет прежнее поведение; явные `false`/`none` также требуют поддержки. Статус официальной публикации и проверки устройств указан в дорожной карте.

### Использование

1. На Android 7.0 или новее установите официальный APK из [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/releases) после публикации или используйте мастер центра плагинов AutoJs6 после включения в официальный индекс. До публикации используйте для тестирования сборку от сопровождающего или соберите исходный код. Значок в лаунчере открывает собственный главный экран.
2. На главном экране проверьте авторизацию и установщик по умолчанию, затем выберите один или несколько пакетов. Подтвердите установку в выбранном диалоге или уведомлении; следите за активными задачами и недавней историей.
3. Для интеграции с AutoJs6 используйте сборку 5299 (6.8.0) или новее и включите `3-Setup Installer` в центре плагинов. API скриптов требует сборку 5300 или новее. Dhizuku, установка через уведомления и параметры постоянного установщика в скриптах требуют AutoJs6 6.8.0, сборка 5307 или новее, с контрактом установщика V2. Базовая интеграция с хостом доступна со сборки 5299, методы скриптов V1 - со сборки 5300.
4. Используйте действие установки в AutoJs6 или выберите 3-Setup Installer при открытии или передаче файлов пакетов. Если появился диалог подтверждения, проверьте приложение и параметры перед установкой. Для привилегированного способа заранее подготовьте авторизацию Shizuku, Root или Dhizuku.
5. Меню главного экрана открывает установленные приложения и настройки. Проверьте локальные параметры установки, внешний вид, значок и уведомления; сведения о приложении, история версий и ручная проверка обновлений находятся в настройках.

### Способы авторизации

- `none`: стандартная сессия PackageInstaller; Android запрашивает у пользователя подтверждение каждой установки, split-пакеты поддерживаются, привилегированные параметры недоступны.
- `shizuku`: требуется работающий Shizuku (запущенный через беспроводную отладку, ADB или Root) и отдельное разрешение для 3-Setup Installer. Разрешение для AutoJs6 не распространяется на этот плагин. Установка, удаление и операции для других пользователей используют права работающего сервиса Shizuku.
- `root`: требуется устройство с Root и менеджер Root, предоставляющий `su` для 3-Setup Installer. Через libsu доступны привилегированные установка, удаление, операции с пользователями и установщиком по умолчанию. Разрешение каждой операции по-прежнему определяется Android и политиками ROM.
- `dhizuku`: требуются Android 8.0 (API 26)+, активный владелец устройства/профиля Dhizuku и разрешение для этого плагина. Операции выполняются только в текущем пользователе владельца, а установщиком указывается реальный пакет владельца. Недоступны возможности shell/root: понижение версии, тестовые пакеты, обход ограничения низкого targetSdk, другие пользователи, произвольный установщик и удаление с сохранением данных. Плагин не назначает владельца.
- **Примечание:** Скрипты по умолчанию используют `interaction: 'auto'` и при наличии привилегий устанавливают без диалога. Действия установки в интерфейсе хоста используют `dialog`. Если Android требует подтверждение, `auto` разрешает его и отмечает это в `notes`. Для подтверждения перед установкой явно укажите `interaction: 'dialog'`. Явный `silent` завершается с `AUTHORIZER_REQUIRED`, если привилегий нет или нужно системное подтверждение.
- Настройки сохраняют порядок и включенное состояние методов авторизации, параметры установки и уведомлений. Установка с главного экрана или из внешнего источника по умолчанию использует `dialog`; можно явно выбрать `auto`, `silent` или `notification`. Кнопки установки в интерфейсе хоста используют `dialog`, скрипты сохраняют явные параметры и по умолчанию используют `auto`. Изменения сохраняются после подтверждения.

### Совместимость

- Android 7.0 (API 24) и новее. Проверка устройств и оставшийся охват описаны в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md).
- Обход блокировки низкого targetSdk существует начиная с Android 14 (API 34); на более старых системах параметр игнорируется с пометкой в результате.
- Страница установщика по умолчанию различает обычные предпочтения и постоянную политику. Обычные предпочтения используют Shizuku или Root и зависят от ограничений прошивки. Постоянная политика через Dhizuku доступна на API 26-33; на API 34+ запрос отклоняется до изменений, поскольку нельзя проверить обратный вызов владельца. Root использует помощник с системным UID только в пользователе 0 на поддерживаемых устройствах. Конкурирующие постоянные политики не перезаписываются. `persistentConfigured` - запись о ранее успешной настройке, а не доказательство текущей политики; пассивная проверка сообщает только `preferred` или `none`.
- `dhizuku`: требуются Android 8.0 (API 26)+, активный владелец устройства/профиля Dhizuku и разрешение для этого плагина. Операции выполняются только в текущем пользователе владельца, а установщиком указывается реальный пакет владельца. Недоступны возможности shell/root: понижение версии, тестовые пакеты, обход ограничения низкого targetSdk, другие пользователи, произвольный установщик и удаление с сохранением данных. Плагин не назначает владельца.
- Запрос разрешений и DexOpt кроме none требуют Shizuku/Root; verify требует API 26+. Причина установки требует API 26+, источник API 33+, запрос владельца обновлений API 34+. Владение включается только при первой установке; обновления или пакет у другого пользователя могут игнорироваться. false не отзывает существующего owner.
- none/Dhizuku проверяет установленные подписи только текущего пользователя; Shizuku/Root выполняет глобальный запрос. При правилах SharedUID невозможность исключить пакет у другого пользователя блокирует без исключения.

### Частые вопросы

- **Почему установка все еще требует подтверждения?** `none` всегда требует подтверждения Android. Политика Android может требовать его и для привилегированных методов. В режиме `notification` системное подтверждение открывается только действием уведомления; этот режим не обходит подтверждение Android.
- **Можно ли установить `.aab`?** Нет. Android App Bundle является форматом публикации; сначала преобразуйте его с помощью bundletool в набор `.apks`. Плагин распознает файлы `.aab` и показывает сведения о пакете и модулях.
- **Почему понижение версии может не сработать с `allowDowngrade: true`?** Параметр лишь запрашивает понижение; Android принимает решение по прошивке, привилегированной учётной записи и признаку debuggable у приложения. Проверенные user-прошивки Sony G8441 / API 28 и Xiaomi 23046RP50C / API 35 отклонили понижение для пакетов без debuggable, а Sony XQ-DQ72 / API 33 с Root его разрешил. Эти результаты относятся только к указанным устройствам. Проверьте ошибку и `systemMessage`; Root не гарантирует понижение на любой ROM.
- **Какое имя пакета установщика использовать в HyperOS?** Если Shizuku запущен через ADB или беспроводную отладку, без указанного имени используется `com.android.shell`. На проверенном Xiaomi 23046RP50C / HyperOS / API 35 новые установки и обновления без диалога записали это значение. Явно указанные `com.android.shell` и имя пакета самого плагина также были приняты и записаны как запрошено. Другие имена или версии ROM зависят от ответа системы.
- **ColorOS или другая ROM требует активировать плагин. Что делать?** После установки или принудительной остановки Android может сохранять приложение остановленным до действия пользователя. Используйте действие активации в центре плагинов AutoJs6, если оно предложено, либо откройте 3-Setup Installer через его значок и повторите попытку. Это соответствует [правилам остановленного состояния Android](https://developer.android.com/reference/android/content/pm/ApplicationInfo#FLAG_STOPPED). Поведение именно ColorOS на устройстве пока не проверено.
- **Почему изменение установщика по умолчанию может не сработать, а сохраненная отметка постоянной настройки - отличаться от текущего обработчика?** Страница установщика по умолчанию различает обычные предпочтения и постоянную политику. Обычные предпочтения используют Shizuku или Root и зависят от ограничений прошивки. Постоянная политика через Dhizuku доступна на API 26-33; на API 34+ запрос отклоняется до изменений, поскольку нельзя проверить обратный вызов владельца. Root использует помощник с системным UID только в пользователе 0 на поддерживаемых устройствах. Конкурирующие постоянные политики не перезаписываются. `persistentConfigured` - запись о ранее успешной настройке, а не доказательство текущей политики; пассивная проверка сообщает только `preferred` или `none`.
- **Почему источник не удален?** Удаление выполняется только после успешной установки. При ошибке, отмене или истечении времени установки источник всегда сохраняется. Ошибка удаления не меняет успешный результат установки, а внешний поставщик может отказать в удалении. Для скриптов хост применяет `deleteSource` к путям и источникам `file://`, сохраняя источники `content://`. Проверьте `sourceDeleted` и `notes`. В пакетной установке для подтверждённо успешных элементов применяется `deleteSource`, даже если другой элемент завершился ошибкой или оставшаяся очередь отменена.
- **Можно повторить или возобновить установку?** Повторная попытка для внешнего URI возможна, пока доступны источник и доступ к нему. После освобождения источника или разрешения откройте пакет заново. После перезапуска процесса восстановленный экран показывает сохраненные подтвержденные результаты и отмечает незавершенные элементы как прерванные. Экран доступен только для чтения и не запускает установку или повторную попытку автоматически. Перед новой попыткой проверьте фактическое состояние приложения.

### Разрешения и безопасность

- Точки входа Binder защищены сигнатурным разрешением `org.autojs.permission.PLUGIN`, поэтому доступ к ним есть только у AutoJs6; внешний пункт "Открыть с помощью" принимает только файлы пакетов и никогда не запускает скрипты.
- REQUEST_INSTALL_PACKAGES и REQUEST_DELETE_PACKAGES обеспечивают подтверждение Android. QUERY_ALL_PACKAGES используется для управления установленными приложениями, сравнения версий и подписей и определения установщика по умолчанию. Обычное разрешение ENFORCE_UPDATE_OWNERSHIP используется для явного запроса владения обновлениями и не гарантирует назначение owner.
- FOREGROUND_SERVICE и FOREGROUND_SERVICE_DATA_SYNC обеспечивают установку и временный доступ к источнику; POST_NOTIFICATIONS разрешает уведомления. Режим `notification` требует включенных уведомлений и канала установки. Остальные режимы работают без разрешения на уведомления.
- Shizuku, Root и Dhizuku используются для запрошенных операций. Плагин не назначает владельца устройства/профиля. Правила постоянного установщика меняются только при запрошенной настройке или очистке; исходные пакеты никуда не загружаются.
- Установка, проверка, история и управление приложениями работают офлайн. INTERNET используется только при ручной проверке версий через фиксированный GitHub Releases API плагина с интервалом 12 часов. Фоновые проверки обновлений и отправка пакетов не выполняются.
- Исходные пакеты открываются только для чтения. История сохраняет ограниченные метаданные и результаты без содержимого пакетов и URI источников; пути в ошибках скрываются. Закрытое хранилище исключено из резервных копий. Удаление записи не удаляет приложение или его исходный файл.
- Параметр запрашивает разрешения, которые система может выдать, включая доступные установщику app-op, например USE_FULL_SCREEN_INTENT на Android 14. Он не гарантирует все разрешения и не выдает доступность, наложения или произвольные разрешения подписи. Ограничения restricted/system-fixed/policy-fixed сохраняются без дополнительного флага allowlist.
- Проверка подписи и локальные точные списки блокировки пакетов/SharedUID действуют для всех входов с `BLOCKED_BY_POLICY`. Только настоящий dialog разрешает одно исключение для подписи mismatch/unknown текущего элемента; Android продолжает проверку. Тихий/notification режим не разрешает исключение, список блокировки не обходится. Предпросмотр показывает объявленные разрешения выбранных APK, а не выданные.

Руководство по установке и текущий прогресс смотрите в [README проекта](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer) и [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md).
