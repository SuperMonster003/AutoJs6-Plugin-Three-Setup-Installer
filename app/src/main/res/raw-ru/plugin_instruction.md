3-Setup Installer устанавливает, обновляет, проверяет и удаляет приложения Android с собственного главного экрана, через AutoJs6 и скрипты, а также при открытии и передаче пакетов из других приложений. Поддерживаются подтверждение Android и привилегированные операции через Shizuku или Root.

1.0.0 описывает реализованные ниже функции установки, управления приложениями и скриптов. Официальная публикация в GitHub Releases и включение в центр плагинов ещё не выполнены. Интеграция требует AutoJs6 >= 6.8.0 (5299), а API скриптов `installer` требует сборку 5300 или новее. Проверенные устройства и оставшиеся проверки указаны в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md).

### Использование

1. На Android 7.0 или новее установите официальный APK из [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/releases) после публикации или используйте мастер центра плагинов AutoJs6 после включения в официальный индекс. До публикации используйте для тестирования сборку от сопровождающего или соберите исходный код. Значок в лаунчере открывает собственный главный экран.
2. На главном экране проверьте авторизацию и установщик по умолчанию, затем кнопкой добавления выберите один или несколько пакетов. Проверьте диалог установки перед подтверждением; прогресс и последние записи видны на главном экране.
3. Для интеграции с AutoJs6 используйте сборку 5299 (6.8.0) или новее и включите `3-Setup Installer` в центре плагинов. API скриптов требует сборку 5300 или новее.
4. Используйте действие установки в AutoJs6 или выберите 3-Setup Installer при открытии или передаче файлов пакетов. Если появился диалог подтверждения, проверьте приложение и параметры перед установкой. Для привилегированного способа заранее подготовьте авторизацию Shizuku или Root.
5. Меню главного экрана открывает установленные приложения и настройки. Проверьте локальные параметры установки, внешний вид, значок и уведомления; сведения о приложении, история версий и ручная проверка обновлений находятся в настройках.

### Способы авторизации

- `none`: стандартная сессия PackageInstaller; Android запрашивает у пользователя подтверждение каждой установки, split-пакеты поддерживаются, привилегированные параметры недоступны.
- `shizuku`: требуется работающий Shizuku (запущенный через беспроводную отладку, ADB или Root) и отдельное разрешение для 3-Setup Installer. Разрешение для AutoJs6 не распространяется на этот плагин. Установка, удаление и операции для других пользователей используют права работающего сервиса Shizuku.
- `root`: требуется устройство с Root и менеджер Root, предоставляющий `su` для 3-Setup Installer. Через libsu доступны привилегированные установка, удаление, операции с пользователями и установщиком по умолчанию. Разрешение каждой операции по-прежнему определяется Android и политиками ROM.
- **Примечание:** Скрипты по умолчанию используют `interaction: 'auto'` и при наличии привилегий устанавливают без диалога. Действия установки в интерфейсе хоста используют `dialog`. Если Android требует подтверждение, `auto` разрешает его и отмечает это в `notes`. Для подтверждения перед установкой явно укажите `interaction: 'dialog'`. Явный `silent` завершается с `AUTHORIZER_REQUIRED`, если привилегий нет или нужно системное подтверждение.
- Настройки сохраняют порядок и включённые способы авторизации, параметры установки и уведомления о прогрессе. Установка с главного экрана и из внешних приложений по умолчанию использует `dialog`; явно сохранённые `auto` или `silent` применяются. Запросы хоста/скриптов сохраняют явные параметры, а API скриптов по-прежнему использует `auto` по умолчанию. Выбор сохраняется только после подтверждения.

### Совместимость

- Android 7.0 (API 24) и новее. Проверка устройств и оставшийся охват описаны в [ROADMAP.md](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Setup-Installer/blob/master/ROADMAP.md).
- Обход блокировки низкого targetSdk существует начиная с Android 14 (API 34); на более старых системах параметр игнорируется с пометкой в результате.
- Политики ROM и существующие настройки по умолчанию могут ограничивать смену установщика по умолчанию. Версия 1.0.0 не гарантирует постоянное закрепление; имя пакета установщика и активация плагина описаны в FAQ.

### Частые вопросы

- **Почему установка все еще требует подтверждения?** `none` всегда использует системное подтверждение. Подготовьте авторизацию и выберите Shizuku или Root в диалоге установки. Android или политика устройства все равно могут потребовать подтверждение.
- **Можно ли установить `.aab`?** Нет. Android App Bundle является форматом публикации; сначала преобразуйте его с помощью bundletool в набор `.apks`. Плагин распознает файлы `.aab` и показывает сведения о пакете и модулях.
- **Почему понижение версии может не сработать с `allowDowngrade: true`?** Параметр лишь запрашивает понижение; Android принимает решение по прошивке, привилегированной учётной записи и признаку debuggable у приложения. Проверенные user-прошивки Sony G8441 / API 28 и Xiaomi 23046RP50C / API 35 отклонили понижение для пакетов без debuggable, а Sony XQ-DQ72 / API 33 с Root его разрешил. Эти результаты относятся только к указанным устройствам. Проверьте ошибку и `systemMessage`; Root не гарантирует понижение на любой ROM.
- **Какое имя пакета установщика использовать в HyperOS?** Если Shizuku запущен через ADB или беспроводную отладку, без указанного имени используется `com.android.shell`. На проверенном Xiaomi 23046RP50C / HyperOS / API 35 новые установки и обновления без диалога записали это значение. Явно указанные `com.android.shell` и имя пакета самого плагина также были приняты и записаны как запрошено. Другие имена или версии ROM зависят от ответа системы.
- **ColorOS или другая ROM требует активировать плагин. Что делать?** После установки или принудительной остановки Android может сохранять приложение остановленным до действия пользователя. Используйте действие активации в центре плагинов AutoJs6, если оно предложено, либо откройте 3-Setup Installer через его значок и повторите попытку. Это соответствует [правилам остановленного состояния Android](https://developer.android.com/reference/android/content/pm/ApplicationInfo#FLAG_STOPPED). Поведение именно ColorOS на устройстве пока не проверено.
- **Почему не удается назначить установщик по умолчанию?** ROM может отклонить изменение. В старых версиях Android существующий обработчик APK может требовать сначала сбросить его настройки по умолчанию в системных настройках; следуйте указаниям страницы. Если система не предоставляет такого действия, замена не гарантируется. Версия 1.0.0 не гарантирует постоянное закрепление даже с Shizuku или Root.
- **Почему источник не удален?** Удаление выполняется только после успешной установки. При ошибке, отмене или истечении времени установки источник всегда сохраняется. Ошибка удаления не меняет успешный результат установки, а внешний поставщик может отказать в удалении. Для скриптов хост применяет `deleteSource` к путям и источникам `file://`, сохраняя источники `content://`. Проверьте `sourceDeleted` и `notes`. В пакетной установке для подтверждённо успешных элементов применяется `deleteSource`, даже если другой элемент завершился ошибкой или оставшаяся очередь отменена.
- **Можно повторить или возобновить установку?** Повторная попытка для внешнего URI возможна, пока доступны источник и доступ к нему. После освобождения источника или разрешения откройте пакет заново. После перезапуска процесса восстановленный экран показывает сохраненные подтвержденные результаты и отмечает незавершенные элементы как прерванные. Экран доступен только для чтения и не запускает установку или повторную попытку автоматически. Перед новой попыткой проверьте фактическое состояние приложения.

### Разрешения и безопасность

- Точки входа Binder защищены сигнатурным разрешением `org.autojs.permission.PLUGIN`, поэтому доступ к ним есть только у AutoJs6; внешний пункт "Открыть с помощью" принимает только файлы пакетов и никогда не запускает скрипты.
- REQUEST_INSTALL_PACKAGES и REQUEST_DELETE_PACKAGES обеспечивают подтверждение Android. QUERY_ALL_PACKAGES используется для управления установленными приложениями, сравнения версий и подписей и определения установщика по умолчанию.
- FOREGROUND_SERVICE и FOREGROUND_SERVICE_DATA_SYNC обеспечивают фоновую работу установки; POST_NOTIFICATIONS разрешает уведомления о ходе и результате. Отсутствие разрешения на уведомления не блокирует установку.
- Shizuku и Root используются только для запущенной вами операции; привилегированный сервис не хранит состояние, не держит открытый shell между операциями и недоступен извне плагина.
- Установка, проверка, история и управление приложениями работают офлайн. INTERNET используется только при ручной проверке версий через фиксированный GitHub Releases API плагина с интервалом 12 часов. Фоновые проверки обновлений и отправка пакетов не выполняются.
- Исходные пакеты открываются только для чтения. История сохраняет ограниченные метаданные и результаты без содержимого пакетов и URI источников; пути в ошибках скрываются. Закрытое хранилище исключено из резервных копий. Удаление записи не удаляет приложение или его исходный файл.
